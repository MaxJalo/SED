# MCP-шлюз СЭД

Локальный stdio-процесс [`services/mcp`](../services/mcp), который даёт ИИ-агенту (Cursor) повседневные глаголы работы с СЭД поверх REST API `/v1`.

Шлюз не содержит своей бизнес-логики, не проверяет контуры локально и не ходит в PostgreSQL, файловый том или 1С: все проверки прав, контуров, маршрутов и аудит выполняются сервером `/v1`.

## Подключение и запуск

- Транспорт: `stdio` (JSON-RPC 2.0, построчный обмен).
- Команда запуска из корня репозитория: `go run -C services/mcp .` (или `go run .` внутри `services/mcp`).
- Переменные окружения:
  - `SED_API_URL` — адрес API (по умолчанию `http://localhost:8000`).
  - `SED_TOKEN` — Bearer-токен текущей сессии сотрудника (тот же, что используется в веб-клиенте). В репозиторий и конфигурацию токен не записывается.
- Пример конфигурации для Cursor находится в [`.cursor/mcp.json`](../.cursor/mcp.json) и берёт токен из переменной окружения `${env:SED_TOKEN}`.
- Ошибки `/v1` передаются модели как ошибка инструмента в виде `HTTP <код>: <сообщение>`.

## Десять инструментов

| Инструмент | Вызов `/v1` | Назначение |
| --- | --- | --- |
| `whoami` | `GET /v1/profile` | Текущий сотрудник, роли, права на контуры и доступные виды документов. |
| `find` | `GET /v1/documents`, `GET /v1/tasks`, `GET /v1/directory` | Поиск документов (`kind=documents`), своих задач (`kind=tasks`, по умолчанию `tab=to_me`) или сотрудников (`kind=people`). |
| `open_document` | `GET /v1/documents/{id}` | Карточка документа целиком. |
| `create_draft` | `POST /v1/documents` | Создание черновика с автоматическим `Idempotency-Key` от канонического JSON. |
| `start_route` | `POST /v1/documents/{id}/route` | Запуск маршрута уже созданного черновика (передаёт только `{"action":"start"}`). |
| `attach_file` | `POST /v1/files` | Загрузка обычного локального файла по абсолютному пути с заголовками `X-Document-Id` и `X-File-Name`. |
| `save_file` | `GET /v1/files/{id}` | Скачивание вложения в указанную папку на диске и возврат сохранённого пути. |
| `decide_task` | `POST /v1/tasks/{id}/decide` | Вынесение решения по своей задаче с маппингом исхода в код API. |
| `comment` | `POST /v1/documents/{id}/comments` | Добавление комментария к документу. |
| `link_documents` | `POST /v1/documents/{id}/links` | Связывание двух документов (`ответ`, `основание`, `допсоглашение`, `приложение`, `замена`, `пункт_протокола`). |

### Маппинг исходов `decide_task`

## Что закрыто в шлюзе

- Выдача и отзыв прав юрлица и контуров (`/v1/role-grants`, `/v1/contour-grants`).
- Регистрация номера, списание в дело, правка реквизитов и конструктора шагов маршрута.
- Отзыв, пауза, возобновление и принудительное подписание маршрута.
- Подтверждение исполнения за автора (`accept` / `rework`).
- Прямой доступ к БД, файловому тому, паролям пользователей и 1С.
