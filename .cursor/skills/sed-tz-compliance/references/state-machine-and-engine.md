# Машина состояний, движок маршрутов и 7 примитивов

## 1. Машина состояний карточки документа (9 статусов)

Состояние вычисляется и хранится исключительно на сервере. Автоматический перевод статуса по истечении срока **запрещён**.

| Статус | Допустимые переходы и правила |
| --- | --- |
| `Черновик` | Начальный статус. Правка всех полей, файлов, важности. Переход в `На рассмотрении / согласовании` (старт маршрута) или `Зарегистрирован` (входящий). |
| `На рассмотрении / согласовании` | Правка полей автором закрыта (кроме дозаполнения пустых второстепенных полей после поэтапной регистрации). Новый файл выпускает версию `N+1`. Режим экземпляра маршрута может быть `active` или `Приостановлено` (пауза статус карточки не меняет). |
| `Возвращён на доработку` | От согласующего/подписанта с обязательной причиной. Автор правит, отмечает учёт замечаний (`remark_addressed`), перезапускает с шага 1. |
| `Отозван автором` | Самоличный отзыв с обязательной причиной (у входящего — до резолюции; у прочих — пока не созданы поручения в `platform_tasks`). Перезапуск с шага 1. |
| `Отклонён` | Финальная остановка при отказе (кроме шага `review`, где отказ возвращает на `resolution`). Продолжение только новой карточкой со связью `основание`. |
| `На подписи` | Автоматически после завершения согласования (или досрочно при `allow_early_sign = true`). |
| `Подписан` | Фиксация факта, даты и `version_id`. При `customer_contract = true` — однократный вызов `external_orders`. |
| `Зарегистрирован` | Присвоение номера канцелярией + транзакционная запись в `outbox_events`. |
| `На исполнении` | Активны поручения в `platform_tasks`. Возврат результата исполнителю оставляет статус `На исполнении`. |
| `Закрыт (в деле)` | Канцелярия после закрытия всех поручений и выбора дела (`case_id`). Полная блокировка любых изменений. |

## 2. Семь примитивов шага маршрута (`kind`)

1. `resolution` — руководитель адресата назначает исполнителей, текст задания и целевой срок.
2. `review` — рассмотрение (исполнение с рекомендацией): обязателен `recommendation_text`. Кнопки `Вернуть` и `Отклонить` возвращают на шаг `resolution` без остановки и без смены номера. После завершения запускаются `acknowledgment` и `execution`.
3. `approval` — согласование (`approve`, `return`, `reject`) с привязкой к `version_id` и `content_hash`.
4. `signing` — финальное утверждение версии.
5. `registration` — присвоение номера `M01` и запись в `outbox_events`.
6. `execution` — создание синхронных поручений `platform_tasks` на каждого исполнителя; закрытие только автором.
7. `acknowledgment` — неблокирующее параллельное ознакомление (`is_blocking = false`, `sla_enabled = false`, 0 ч в цикле, не задерживает `execution` и списание в дело).

## 3. Ключевые параметры и правила движка

- **Флаги шаблона шага:**
  - `join_mode`: `all` (по умолчанию) или `any` для одного `parallel_group`.
  - `stop_on_reject`: `true` (по умолчанию снимает незакрытые задачи группы и останавливает маршрут) или `false` (фиксирует отказ в листе и движется дальше).
  - `allow_early_sign`: `false` (по умолчанию) или `true` (разрешает `force_sign` до окончания согласования).
  - `per_file_approval`: `false` (по умолчанию) или `true` (требуется решение по каждому файлу текущей версии).
  - `is_mandatory` / `is_order_locked`: запрещают удаление шага и изменение его порядка при запуске/правке экземпляра.
- **Условность (`condition_rule`):** предикат включения шага на старте (связь с договором, адресат выше руководителя автора, исполнители вне подразделения, порог суммы).
- **Разрешение исполнителей и замещения:** на момент перехода очереди роль разрешается в `user_id` через оргструктуру. При активном серверном замещении задача сразу назначается заместителю с пометкой «за кого». Смена руководителя или включение нового замещения **не переписывают** уже выданные задачи.
- **Делегирование и добавление участника:** текущий исполнитель может делегировать задачу (`delegated_from_user_id`) или добавить согласующего в экземпляр без правки шаблона; `plan_due_at` с нуля не перезапускается.
- **Связи и пауза подчинённых:** возврат на доработку или отзыв родительской карточки автоматически ставит согласование подчинённых документов на паузу (`Приостановлено`); отказ по родителю подчинённые документы автоматически не закрывает. Связь `замена` исходный документ автоматически не закрывает.
- **Боковая рецензия:** может запрашиваться вне этапа согласования; SLA не запускает, статус не меняет.
- **Лист согласования (`.docx`):** содержит участников, версии, решения, комментарии, отметки об учёте замечаний, плановые/фактические даты, отклонения SLA и графическое факсимиле (при наличии). Наличие факсимиле не заменяет фиксацию факта подписания в БД.
